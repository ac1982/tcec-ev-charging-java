# 安全、生命周期与部署

## 密钥与认证

`PartnerCredentials` 按每个对端及通信方向配置。当前明确采用 UTF-8 原文密钥配置方式：AES key 和 IV 各 16 字节，签名密钥非空。不会猜测、自动 hex 解码或 Base64 解码密钥。协议的固定 IV 和 HMAC-MD5 是兼容性需求，不能替代 TLS。

客户端默认只允许正常证书校验的 HTTPS；不跟随重定向。明文 HTTP 仅在显式开启测试选项且地址为 loopback 时可用。MVC 接收端由宿主应用提供 TLS 或受信任的 TLS 终止代理；此 starter 自身不配置证书，也不会在明文公网部署时自动获得安全保护。

接收处理顺序：限制请求大小 → 严格解析信封 → 查可信运营商 → 校验 MAC → 校验 bearer（query_token 除外）→ 时间/防重放 → 解密并验证类型化负载 → 业务处理器。

- 未知运营商无法可信地签名响应，返回空 HTTP 401；未能解析信封返回空 HTTP 400。
- 已识别运营商的协议错误使用 HTTP 200 和签名错误信封。Ret：4001 签名、4002 令牌、4003 信封/时效/重放、4004 业务负载、500 服务端错误。
- 错误 Data 统一为空字符串，Msg 为通用安全描述。这是明确的对接策略，须与对端确认，不声称规范统一规定了此形式。
- 不记录密钥、令牌、明文报文或设备操作码。凭证、令牌 DTO、信封与带 IdentCode 的通知重写了 toString；其他业务 DTO 仍可能包含业务信息，应用日志应使用白名单摘要。
- JSON 禁止重复字段、尾随内容、未建模字段、浮点→整数和数字/布尔→字符串转换。解析嵌套上限64，数字长度上限128。唯一元数据例外是内置请求DTO根部的64位整数serialVersionUID；它不参与业务且不会输出。

DTO本身可表示缺省/null字段。`RequestValidation` 在客户端发送前及请求解码后执行所需标识、序列长度与列表约束；业务处理器还必须验证操作权限、设备状态、金额范围、日期范围和订单一致性。

单独使用 `TcecCodec.decodeRequest` 只完成报文身份/签名/解密、类型和请求边界校验，不代替 bearer、时效和防重放策略。使用完整 MVC 接收链路，或按上述顺序组合 SPI。

## 令牌

令牌签发验证外层和内层 OperatorID 以及 OperatorSecret。成功结果要求已验证的OperatorID、SuccStat=0、非空合法bearer token、正有效期且不超过7天。FailReason可省略或为0，显式非零仍拒绝。响应外层的可选OperatorID只做一致性检查，不能替代MAC；默认有效期 2 小时。业务失败与外层成功分别处理。

`InMemoryTokenStore` 每运营商保存一个活动令牌；有效期内原子复用且不延长到期时间，到期后重新签发。过期严格拒绝，容量耗尽时不会驱逐仍有效的其他运营商令牌。生成使用 SecureRandom；比较使用常量时间字节比较。不同调用方向/对端应使用各自存储命名空间。

`TcecSession` 提供与单个客户端和运营商绑定的客户端令牌缓存/并发刷新；具体用法与行为参见客户端 JavaDoc。裸 `TcecClient` 可供已有令牌管理系统使用，调用者必须自行验证 query_token 返回身份和业务状态。

集群部署必须替换 `TokenStore` 和 `ReplayStore` Bean，以共享原子数据源实现，并设置 `tcec.server.require-shared-stores=true` 防止无意使用默认内存Bean。该开关是显式装配保护，不会自动证明自定义Bean真的共享；部署方仍须检查。内存实现仅适合单 JVM；重启会丢失状态，不能视为持久化安全存储。运营商注册表由部署方管理和轮换，不提供默认生产密钥。

## 时钟与重放

默认协议时区 Asia/Shanghai、接收允许偏差 ±5 分钟；二者是可配置策略。时间格式严格解析；MAC 认证前不占用重放缓存。重放键为运营商、时间戳和完整已认证信封字段的长度定界SHA-256指纹，包含Seq、密文和MAC，不包含未签名的HTTP路径。这样相同秒/Seq但不同的已认证报文可通过；完全相同报文仍拒绝，包括尝试改路由重放。保留到整个时间接收窗口结束（包含未来偏移），内存容量满时拒绝新请求，不驱逐仍有效条目。

客户端同一实例并发生成每秒 0001～9999 序号；耗尽则抛错，不复用。按对端和通信方向复用客户端。多个活跃进程使用相同身份时，完全相同的密文/时间/序号会形成真正相同报文并被拒绝；库的单实例计数器不是分布式序号分配器。独立业务操作需独立业务ID和应用级幂等。

保持系统时钟同步。业务幂等应根据 StartChargeSeq、订单/对账 ID 等独立实现，不能把信封防重放当作业务幂等。

## 超时、限制与重试

客户端默认连接超时 10 秒、完整响应超时 30 秒、响应体 2 MiB；服务端请求体默认 2 MiB。配置适配合理的站点分页大小。宿主容器/代理还应配置请求读取超时、并发限流、连接数和 header 大小上限，避免慢速上传占用线程。

客户端不自动重试业务 POST，不追随重定向，不因 token 错误自动重放启停充电。超时可能发生在对端已经执行之后，应由业务层查单/查询状态并保留原业务 ID 后决定重试。

CEC 第4部分包含协议重发要求（大于3次，建议间隔1分钟）；重试调度和幂等由应用承担，本库没有后台重试队列。站点状态通知响应 Status=1 表示忽略且不应重试。不要把该值解释成需要重发的网络故障。

## 上线前

- 对端确认版本、路径、双向密钥格式、时区、时钟偏差、错误 Data 约定
- 使用真正业务处理器、共享令牌/重放存储和业务幂等
- 验证 TLS、入口限流/读超时、权限边界和密钥轮换
- 在运营商测试环境核对正常与失败场景，再上线

## 可选Redis实现

加入 `tcec-store-redis` 后，使用应用管理的 Jedis `RedisClient` 显式注册两个Bean：

```java
@Bean
TokenStore tokenStore(RedisClient redis) {
    return new RedisTokenStore(redis, "charging-inbound");
}
@Bean
ReplayStore replayStore(RedisClient redis) {
    return new RedisReplayStore(redis, "charging-inbound");
}
```

实现类型在 `io.github.ac1982.tcec.redis`；SPI在 `.security`。Redis连接池、地址、TLS、认证和生命周期由宿主应用管理，SDK不会创建默认生产连接或保存凭证。同一集群的同一通信方向使用相同命名空间；不同服务/方向使用不同命名空间。

- 令牌使用单键Lua脚本原子签发/复用，Redis服务器时间与到期值共同决定有效期；不会无意延长已有令牌。
- 重放使用单键原子 `SET NX PXAT`，按完整接收窗口到期，默认最长两天加一秒。拒绝无效或超范围到期时间，不缩短安全窗口。
- 连接失败时令牌签发报告通用错误；令牌验证和重放声明失败关闭，不降级到内存或跳过认证。
- Redis必须启用适当持久化、访问控制、TLS、限流和 `noeviction`，避免活跃重放键被驱逐。Redis数据丢失会丢失重放保护；恢复服务前须按接收时窗制定安全恢复策略。
- 集成测试使用真实独立Redis进程验证多实例原子性、隔离、到期和故障；不意味着验证了任意Redis集群、故障转移拓扑或生产运维配置。
